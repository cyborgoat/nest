# 发布知识包与查看消息

从最左侧活动栏打开 **Source Control** 来发布修改；从顶部栏右上角打开 **Messages**
查看审核结果。

| 目标 | 使用方式 |
| --- | --- |
| 直接向他人发送副本 | **Export ZIP** |
| 在团队目录中提供一个版本 | **Publish** 到 Hub |

## 分享 ZIP

在知识包操作中选择 **Export ZIP**，把文件发送给其他 Nest 用户。对方可通过
**Hub → Import → Import pack ZIP** 添加。导出不需要账户或 Hub 连接。

## 发布到 Hub

需要 Hub 连接、有发布权限的账户，并且该知识包没有正在审核的申请。

1. 在最左侧的 **Source Control** 中审查每项修改。
2. 使用知识包的 **Publish** 操作。
3. 选择 **New release**（发布新版本号）或 **Live patch**（更新现有版本的文件）。
4. 填写简洁的发布提交消息，说明本次变更。
5. 在 **Under Review** 或 **Messages** 中查看结果。

只有当知识包与当前已发布版本不同时，Nest 才允许提交。仅修改版本号不算变更；请先
编辑文件，或在发布新版本时更新描述。实时补丁始终需要包含文件变更。

新知识包的首次发布通过审核后，提交者会成为该知识包的署名作者，并自动加入
维护者列表。Hub 知识包详情会显示作者和当前维护者；管理员可在管理后台中
分别修改作者归属和维护权限。

## 提交之后

- **Pending**：知识包会被锁定，只读提示会显示提交者。原始提交者可在 **Under Review**
  取消申请；其他用户不会看到取消链接。
- **Approved**：在 **Messages** 或 **Source Control** 中选择 **Merge with remote**。
  无冲突内容自动合并；冲突文件可选择 **Local** 或 **Approved Hub**。
- **Rejected**：在 **Messages** 中阅读审核意见，修改后可再次发布。

获批的实时补丁会显示为 **Patch available**。前往 **Hub → Installed** 选择
**Sync patch**；本地修改发生冲突时会使用同一套逐文件解决界面。
