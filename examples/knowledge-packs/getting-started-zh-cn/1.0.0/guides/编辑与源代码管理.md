# Markdown 编辑与源代码管理

## 编辑 Markdown

打开 Markdown 文件，在编辑器与源代码模式之间切换并正常保存。编辑器与源代码
管理共享同一文件状态，因此丢弃修改也会恢复已打开编辑器中的内容。

Nest 支持 GitHub Flavored Markdown，包括表格、任务列表、删除线、围栏代码块、
链接、本地图片和 Mermaid 图表。

```mermaid
flowchart LR
  Edit[编辑] --> Save[保存]
  Save --> Review[在源代码管理中审查]
  Review --> Publish[发布]
```

## 状态标记

- **M**：已跟踪文件被修改。
- **A**：新增文件。
- **D**：文件被删除。

源代码管理图标上的琥珀色圆点表示存在本地修改。打开文件可与同步基线进行比较。

## 谨慎丢弃

丢弃会从基线恢复修改或删除的文件，并移除新增文件，同时更新已打开的编辑器。
操作前请先查看差异。

## 同步审核状态

发布后使用刷新按钮。申请获批后会显示 **与远程合并** 操作。合并会将 Hub 审核
通过的准确版本设为新基线，并保留本地工作文件，因此提交后的修改仍会显示。申请被
拒绝后会解除待处理锁并显示拒绝标记，可在消息中阅读管理员意见。
