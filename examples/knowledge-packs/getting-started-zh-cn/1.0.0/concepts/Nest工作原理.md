# Nest 工作原理

## 组织知识的共享入口

Nest 旨在集中管理来自不同部门的知识包、配套图片和其他基于 Markdown 的内容。它为
知识提供一个位置明确、可预测的入口，用户无需再针对每种资料前往不同的网站、网盘或
聊天记录。

当知识副本四处分散时，通常很难确认：

- 到哪里查找某份文档；
- 哪个版本是当前版本；
- 某次发布是否正式且已经过审核；
- 谁有权访问受限资料。

Nest 将本地知识库与可选的共享 Hub 结合起来解决这些问题。Hub 记录版本化发布，对
受限知识包执行访问规则，并支持管理员在提交内容正式发布前进行审核。因此，经过批准
的 Hub 发布可以成为清晰、权威的团队知识来源。需要在目录外直接分享时，仍可导出
ZIP。

## 知识包包含什么

Nest 使用普通文件夹、Markdown 文件和支持的图片保存知识。一个知识包会将相关内容
（例如员工手册、设计指南或项目文档）组织成一个整体，以便查找、管理版本和分享。
已安装的知识包包含 `pack.json`，但从文件夹导入前无需手动创建它；Nest 可以收集
元数据并自动生成。

## 基本使用流程

1. 如果组织提供了 Hub，请先在**设置**中连接团队 Hub。
2. 通过 **Hub** 查找已批准的共享知识包，或从文件夹、ZIP 导入。
3. 在**资源管理器**中浏览已安装的知识包并阅读 Markdown 文件。
4. 需要改进或创建知识时，在本地编辑并通过**源代码管理**检查修改。
5. 导出 ZIP 直接分享，或通过 Hub 发布经过审核和版本管理的内容。
6. 知识包所有者发布新版本后，安装已批准的更新。

## 本地优先

知识包保存在你的电脑上。无需登录即可阅读、编辑、导入、导出和检索。Hub 是
用于共享目录、发布、受限知识包访问和审核通知的服务。

## 编辑与分享使用的区域

- **源代码管理**：在发布前查看新增、修改和删除的文件。
- **消息**：记录发布申请、批准与拒绝通知。
- **设置**：管理 Hub、账户、本地存储和可选的聊天配置。

## 版本与发布

Nest 为每个知识包保留一个已安装版本。已发布版本不可修改：请先更改本地文件，
选择更高的语义化版本号，提交该版本，并等待管理员批准或拒绝。审核和版本管理可帮助
读者区分正式的 Hub 发布与尚未发布的本地修改。

## 可选的聊天功能

聊天可使用已启用知识包和 `@` 引用回答问题。停用知识包不会删除内容，仍然可以
阅读，但在重新启用前不会参与普通聊天检索。
